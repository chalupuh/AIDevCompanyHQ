# HiveBoard release checklist (to store submission)

Status 2026-11-12: all 4 milestones approved, release prep done on branch `build/m1` (family-chore-board repo). Items marked **OWNER** need the human; nothing here has been submitted or deployed.

## 0. Audit result (done)
- `expo-doctor`: 18/18 after aligning `expo-sqlite` to ~15.1.4 (was 15.0.6). `expo install --check` clean.
- `expo-iap` 6.4.3 with SDK 52: `expo prebuild --no-install --clean` (temp copy, nothing committed) succeeds and the config plugin runs. iOS prebuild could not run on Windows, so the iOS side is verified only by the EAS iOS build. Runtime behaviour (product fetch, purchase) is still unverified until the dev build + sandbox test below.
- Android permissions now explicit: `POST_NOTIFICATIONS`, `VIBRATE`; blocked `READ/WRITE_EXTERNAL_STORAGE`, `SYSTEM_ALERT_WINDOW`. `INTERNET` and `MODIFY_AUDIO_SETTINGS` remain (Expo defaults; billing needs network). No microphone, camera, location, contacts.
- Identifiers: iOS bundle `com.hiveboard.familychoreboard`, Android package same, version 1.0.0, build numbers via EAS remote (`appVersionSource: remote`, production `autoIncrement`). IAP product id: `hiveboard_full_unlock` (must match in both stores).
- No `NS*UsageDescription` strings are needed (no protected APIs requested). `usesNonExemptEncryption: false` set.

## 3. Builds
- [ ] **OWNER** `eas login` then `eas init`; then Android dev build: `npx eas-cli build --profile development --platform android --non-interactive --no-wait` (first run asks to generate a keystore: answer yes interactively).
- [ ] **OWNER** iOS: `eas device:create` for the test iPhone, then `eas build --profile development --platform ios` (needs Apple credentials, interactive). Simulator build `development-simulator` cannot test real purchases.
- [ ] Production: `eas build --profile production --platform all` after assets are final (needs owner OK).

## 4. IAP product setup (OWNER)
Non-consumable "Full unlock", product id `hiveboard_full_unlock` in both stores.
- App Store Connect: create the app (bundle id above) first; Agreements, Tax, Banking (Paid Apps agreement) must be active; Monetization > In-App Purchases > Non-Consumable; reference name, price tier, localized display name/description, review screenshot (paywall) and review notes. Create a Sandbox tester (Users and Access).
- Play Console: create the app; upload a first AAB to an internal/closed test track (products cannot be created until a build with billing exists); Monetize > In-app products > create `hiveboard_full_unlock`, price, activate. Add license testers (Setup > License testing).
- Merchant/payments profile on Play for paid products.

## 5. Privacy answers (based on code)
Facts: all data in local SQLite on device; no accounts; no analytics/ads SDKs (AC-52); no network calls other than the store billing libraries; no expo-updates. Notifications are local only. Document picker/sharing are user-initiated import/export. Secure-store holds the parent PIN locally.
- Apple App Privacy: "Data Not Collected". Age rating: answer no to all content questions; consider Kids Category (no third-party analytics/ads and parental gate on purchase/restore, which the PIN gate provides; review wording with owner). Export compliance: no non-exempt encryption (already declared).
- Google Data safety: no data collected, no data shared; data is not transmitted off device; no deletion mechanism needed beyond uninstall (state this). Declare ads: none. Target audience: choose deliberately; if "children under 13" is included, Play Families policy applies (needs a compliant privacy policy and no ads SDKs, true here). Declare permissions rationale for POST_NOTIFICATIONS (chore reminders). Content rating questionnaire (IARC).
- OWNER confirms the declared audience (family app vs. Kids/Families program) since it drives extra review.

## 6. Test plan on the dev build
Install the dev build, `npx expo start --dev-client`.
Maestro (flows in `e2e/`): first-run setup, add child, add chore, mark complete, reward, parent PIN gate, reminder time set, offline launch. Run `maestro test e2e/` against Android device/emulator; iOS requires a dev build on device or simulator build.
Sandbox purchase (physical device; emulators without Play Store cannot):
1. Fresh install: launch with airplane mode on, app opens (non-interactive entitlement check, no store sheet).
2. Free-tier limit reached, paywall shows price from the store (confirms `fetchProducts` works with expo-iap 6.4.3).
3. Buy as sandbox/license tester behind the PIN gate; entitlement unlocks immediately; kill and relaunch, still unlocked.
4. Cancel purchase and pending/deferred states do not unlock.
5. Reinstall, Restore purchases (PIN-gated) re-unlocks.
6. Notifications: Android 13+ permission prompt appears, daily reminder fires at set time; iOS same.
7. Refund/revoke in sandbox, entitlement removal on next launch.
