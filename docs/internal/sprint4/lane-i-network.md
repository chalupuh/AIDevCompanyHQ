# Sprint 4, Lane I: Control Room on the home network + phone (StudioControlRoom, branch feat/s4-network)
Goal: open the Control Room from any device on the home LAN (192.168.1.0/24), including the owner's phone, safely. Paths are relative to the StudioControlRoom checkout. `npm --prefix studio/app run build`, `npm --prefix studio/app test` and `node engine/test.js` must pass. Do NOT connect to or change any other machine. Home network only: no port forwarding, no public exposure.

- [x] [backend-dev] LAN bind + token auth in studio/studio.js: bind address from env STUDIO_BIND or machine.json controlRoom.bind (default stays 127.0.0.1). When bound to anything other than loopback, every /api/* request (and the event stream) needs a token: `Authorization: Bearer <t>` or an HttpOnly SameSite=Strict cookie `studio_token`. Token lives in HOME/.studio/auth.json (random 32 bytes, created on first LAN start; `studio.js token rotate` replaces it). Requests from 127.0.0.1/::1 skip auth. Reject non-private source IPs (only 10/8, 172.16/12, 192.168/16, loopback) with 403. Constant-time token compare; 5 failed attempts per IP per minute → 429. `GET /pair?t=<token>` sets the cookie and redirects to /. Selftests in engine/selftest-auth.js (spawn the server on a random port: loopback no token OK, LAN-style request without token 401, with token 200, wrong token 401 and rate limit 429, public IP 403). Run node engine/test.js.
- [x] [backend-dev] Pairing + firewall: `studio.js pair` prints the LAN URL(s) of this host (each private IPv4 + port) with the pairing link and renders a QR code in the terminal (vendor a tiny MIT QR encoder into studio/qr.js, no new npm dependency for the server); also `GET /api/pair-qr` returns an SVG QR for an already-authorised browser so the desktop page can show "Pair phone". `studio/firewall.ps1` adds/removes an inbound Windows Firewall rule "Studio Control Room (LAN)" for the Control Room port with -RemoteAddress LocalSubnet (supports -WhatIf / -Remove). Document in README "Phone and LAN access". Run node engine/test.js.
- [x] [frontend-dev] (MOVED to the separate s4-pwa job on branch feat/s4-pwa; not part of the lane I engine run, reviewers judge Tasks 1-2 only) Phone-friendly Control Room: make studio/app responsive down to 360 px wide (header switch, Team, Operations/Owner Inbox and gate decisions usable one-handed: 44 px touch targets, no horizontal scroll; Village can be a simplified list on narrow screens). Make it an installable PWA: manifest (name "Studio Control Room", icons generated from an existing app asset), a service worker that caches the app shell only (never /api), and theme-color. Show a "Pair phone" button (QR from /api/pair-qr) in settings on desktop. Vitest tests for any new layout/helper logic. Build and tests must pass.
